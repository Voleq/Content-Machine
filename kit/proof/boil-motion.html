The boil, watched — data plates looping at 2fps

The one thing the kit has never done: a data plate actually moving. Everything about the boil in this pack has been arithmetic — byte counts, ink shares, path diffs — and the question asked of it is whether a table that loops can still be read. That cannot be answered by a number, so this page runs the frames on a timer at the fps the manifest declares and lets you watch.

READ THIS FIRST — the premise of the question is wrong, and it is the answer. The 47 plates did not become boiling plates. A plate contains no content; it contains slots. Every figure on a numbers sheet is type the compositor sets into a slot box at video time, and every slot box on every plate here is bit-for-bit identical across all three frames — measured below, 0 units of deviation on 12 plates and 315 slots. The boil was turned on for the plates' furniture, behind a gate: with the gate up a mark takes the boil offset only if it was drawn inside HAND.breathe(). So no number in this kit wobbles, and none can. The type is pinned by construction, not by restraint.

That reasoning is not missing from the pack — it is §1.5 in engine/build.js, written at the point the gate is raised, and it explicitly retracts the old rule and names what is deliberately excluded from the breathing set: axis lines, series lines, slot underlays and highlight boxes. What it does not do is appear in CHANGES.md, which is why the question had to be asked at all. That is a documentation defect and it is real.

AND THE GATE LEAKS, in exactly the place §1.5 names. Thirteen plates draw a band or hatch that moves behind pinned type — the third exclusion, violated. The sharpest case is structure/row-spotlight, whose entire function is a highlight box. Watch the middle column below: the type does not move, the paper under it does, and the relative motion is the thing §1.5 predicted reads worse than either alone.

1 · tables/numbers-sheet-5r — sixty figures, looping

Filled with the worst realistic copy, at the derived budget. Left is the plate as shipped. Middle is the same plate with the bands pinned to frame one and everything else still boiling — the proposed fix, previewed by substituting frame one's band paths rather than by changing a drawing function. Right isolates the moving ink alone, so you can see what is actually in motion.

2 · tables/cash-flow — the gate working correctly

The comparison case, and the reason this is not a blanket finding. Cash-flow boils 12 of 67 marks and not one of them passes under a value box: it has no zebra banding, so its furniture is the paper edge and the rules, which is precisely the set §1.5 intended. Same loop, same fps. If the answer to the brief were "turn the boil off", this plate would be collateral.

3 · structure/row-spotlight — a highlight box, boiling

§1.5 names highlight boxes in its exclusion list by those words. This plate is one, and it moves: 177 band marks under 6 value slots in portrait. It is the clearest thing on this page.

4 · The 1:1 crop — one row, at delivered scale

Everything above is fit to the column. This is a single sheet row at 1:1, where one canvas unit is one CSS pixel, so the band displacement is the real number rather than a scaled one. Shipped against pinned, same crop, same clock.

5 · charts/bars-8q — the hairline case, for completeness

Seven chart plates have exactly one moving mark crossing their value labels: a ~1,605-unit gridline at stroke-width 2.25, displaced 0.83 units — 1.7px delivered. §1.5's own sorting principle covers it (nobody reads a number off a table rule) and at this amplitude I cannot see it move. Included because it is in the measurement and should not be quietly dropped from it.
