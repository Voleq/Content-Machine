# The web page as his main tool — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The localhost panel becomes the place Valentin works: a left menu, a top bar, a workspace per video that walks the ten steps, then Home, Library, Settings, Ideas, Calendar and Stats, with Telegram as the remote.

**Architecture:** The server stays the standard-library HTTP server in `bot/panel.py`. New read-only *views* (`bot/panel_views.py`) turn what the bot already knows into JSON for one screen each, reusing the pipeline functions the commands print from; every action still goes through `run_command` / `handle_callback` / `handle_text` / `handle_upload`, or a new `BotCore` method where no command fits (the same method a Telegram command would call). The page is plain HTML/CSS/JS split into one file per screen under `bot/panel_static/`, no build step, no installs.

**Tech Stack:** Python 3.11 stdlib `http.server`, vanilla JS (ES2020, no framework), the existing CSS tokens (light and dark), Playwright from the container's global node tools for the screenshot check only.

**Spec:** Claude Doc "Build plan: your picks and the web page" rev 9, section "The web page" (https://claude.ai/code/artifact/2fef74dc-c79a-44db-bf87-4ed649a04478); bot inventory in the session notes.

## Global Constraints

- Every control calls the same bot code Telegram uses; the page may show more, never decide differently. No button only pastes a command into a box.
- Keys and passwords are never shown or edited on the page; `state/` is never served (`Panel.allowed`).
- The panel stays on 127.0.0.1 behind the panel key; nothing new to install.
- A confirm before anything that spends money or deletes.
- No 3D switch; the page warns when `DENNIS_3D` is off.
- Wide screen first; plain words and hover help (`title`) on every control; light and dark modes.
- New Telegram commands only where they help remotely.
- Tests never read his `.env` (`_env_file=None`); every text read/write names `encoding="utf-8"`.

## Review Focus

- A video with nothing yet (no lane, no workbook) opens on step 1 with every later step shown as "not yet", not an error — Task 1.
- A view for a workspace whose files are half-written (bad JSON report, missing manifest) still returns, with that section marked unreadable — Task 1.
- The panel key never appears in a view's JSON, and a `path` outside the served roots is never handed to the page as a link — Task 1.
- A switch flipped on the page reaches the running bot's `settings` at once and survives a restart — Task 9.
- A schedule click on a calendar slot with no video ready offers nothing to schedule rather than a broken form — Task 11.

## Part A — the video workspace (merges on its own)

### Task 1: The video view

**Files:** Create `bot/panel_views.py`; modify `bot/panel.py` (`GET /api/video?t=&d=`); test `tests/test_panel_views.py`.

**Interfaces:**
- `video_view(core, ticker, workdate) -> dict` with keys `state` (`VideoState.to_json()`), `steps` (list of `{id, title, status: done|now|todo|skip, summary}` in the order data, angle, write, check, proof, approve, voice, render, upload, live; `angle` is `skip` for a short), and one key per step holding that step's data. Each step's builder is its own function `_step_<id>(core, ws, st) -> dict`, wrapped so an exception becomes `{"error": "…"}` for that step only.
- `data`: `{file, as_of, problems: [{kind, message, blocking}], figures: [{label, value}]}` from `check_export` and `CompanyData`.
- `angle`: `{prompt_url, chosen, awaiting}`; `write`: `{prompt_url, prompt_name, chars}`.
- `check`: `{lines: [{n, text}], findings: [{gate, severity, message, line, excerpt}], claims: [{line, text, why}], cold_read: {text, quotes:[{quote, line}]} | None, cold_prompt, dennis_alone, est_runtime_min, est_render_min, why, revisions}`. Findings come from a new `CostReport.findings: list[dict]` written where gate findings are flattened today (`pipeline/cost.py`, `bot/handlers.py` intake); an old report without it falls back to parsing `L{n}:` out of the strings.
- `proof`: `{url, chapters: [{t, title}], strip: [{t, url}], notes: [...]}`; `approve`: `{est_usd, cached, approved, sha8, mtd, cap}`; `voice`: `{audio_url, words_url, sentences: [{index, text, start, end}], redos_left, rules_hitting: [...]}`; `render`: `{job, progress}`; `upload`: Task 4; `live`: Task 5.
- File links are built with `Panel.file_url` only for paths `Panel.allowed` accepts.

### Task 6: The page shell and the workspace screen

**Files:** Rewrite `bot/panel_static/index.html` (left menu: Home, Videos, Ideas, Calendar, Stats, Library, Settings, Activity, Commands; top bar; one `<main>`; replies drawer; dialogs), split `app.js` into `core.js` (api, store, router `#/<screen>/…`, polling, replies, confirm, toasts) and `screens/{home,videos,video,commands,activity}.js`; extend `app.css`; test `tests/test_workflow.py` (page loads, every script it names is served).

The workspace screen `#/video/T/D[/step]`: a step rail with each step's status and summary, the open step's panel, and the next step's main button always in the same place (top right of the panel). Steps:
1. Data — drop zone (`/api/upload`), as-of, problems, figures.
2. Angle — copy/download the prompt, paste box (`/api/text`), pick 1–3 (`g|` callback).
3. Write — copy/download the prompt, paste box or file drop.
4. Check — numbered lines, tags coloured, click a line to edit in place (`/script edit N text`), Undo (`/script undo`), findings beside it grouped by gate and linked to the line, claims, cold read column (copy prompt, paste answer to `/script coldread`), alone share, length, why box (`/script why`).
5. Proof — Render proof (`q|p|…`), player with chapter marks, frame strip, `,` `.` step a frame, `n` adds a note at the current time, fault list with Copy.
6. Approve — the estimate, then Approve (`a|…` callback) behind a money confirm.
7. Voice — Task 7.
8. Render — stage, percent, time left, last log lines (polled), Stop (`/jobs cancel T`).
9. Upload — copy buttons per field, downloads, the Studio checklist, paste the link (`/publish mark`), or Upload private / Schedule (`u|`, `us|`), thumbnail slot.
10. Live — retention chart (inline SVG), lines where viewers left, corrections, scoreboard.
